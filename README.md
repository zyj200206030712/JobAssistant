# 职路 · 个人求职工作台

一个仅在本机使用的求职管理工具。项目只使用 HTML、CSS、JavaScript 和 JSON，无需安装环境或启动服务器。

## 打开方式

1. 打开 `JobAssistant` 文件夹。
2. 双击 `index.html`。
3. 推荐使用最新版 Chrome、Edge 或 Firefox 浏览器。

全部五个阶段均已完成：

- 项目目录与基础 JSON 数据文件；
- 左侧导航和页面切换；
- 首页求职统计；

## 数据说明

- `data/companies.json`：企业初始数据；
- `data/learning.json`：学习资料初始数据；
- `data/websites.json`：招聘网站初始数据；
- `data/quicklinks.json`：首页常用链接初始数据。

浏览器直接打开本地 HTML 时，出于安全限制不能自动覆写磁盘中的 JSON 文件。本项目采用“JSON 初始数据 + 浏览器本机自动保存 + JSON 导入/导出”的离线方案，保证刷新后数据仍然存在，同时保留可迁移的 JSON 备份。

学习记录的文字和图片元数据保存在常规本机数据中，图片内容保存在浏览器 IndexedDB 图片库。支持 PNG、JPEG、WebP，单张原图不超过 10 MB，每条记录最多 20 张；长边超过 1920 像素时会自动缩小。编辑时粘贴或移除图片只有在点击“保存记录”后才会生效。

工作台只会在成功读取到完整、有效的本机学习数据后，于启动时清理无主图片。清理前会检查学习模块结构、记录 ID 和图片 ID；若数据缺失、损坏或只有部分模块，会保留 IndexedDB 中的现有图片，避免在恢复数据前误删仍可用的图片内容。

旧版 LeetCode 数据或备份中没有 `problemDetail` 字段时仍可正常加载和导入，详情页会提示“暂未填写题目详情”；再次编辑该记录时需要补充题目详情后才能保存。

合并旧版学习备份时，如果导入记录没有 `images` 字段，相同 ID 的现有记录会保留当前图片；如果导入记录明确包含空的 `images` 数组，或选择“覆盖对应数据”，则以导入内容为准。

旧版模拟面试记录会优先将“我的回答”迁移为新的“回答”字段；如果“我的回答”为空，则使用原“参考答案”。问题类型和复盘字段不再保留。

## 备份与恢复

1. 打开“设置”。
2. 点击“选择位置并导出”。Chrome 或 Edge 会弹出“另存为”窗口，可选择项目的 `JobAssistant` 文件夹；图片较多时文件会明显变大。
3. 默认文件名包含日期和时间，避免同一天多次备份互相覆盖。不支持文件选择窗口的浏览器会回退到默认下载目录。
4. 恢复时选择或拖入该文件。
5. 选择“合并现有数据”或“覆盖对应数据”，然后确认导入。

建议在清理浏览器数据、更换浏览器、移动项目文件夹或更换电脑前先导出备份。旧版不含 `images` 字段的备份仍可直接导入。

## 本地文件自动同步

1. 建议使用最新版 Chrome 或 Edge 打开工作台。
2. 先使用“导出 JSON”生成备份文件，或准备一个已有的工作台 JSON 文件。
3. 进入“设置”，点击“绑定本地备份文件”并选择该文件。绑定只记录文件位置，不读取内容，也不会写入或覆盖文件；重新绑定后自动同步默认关闭。
4. 从文件恢复数据时，必须使用“JSON 数据备份”区域的“导入 JSON”，不能使用“绑定”或“立即同步”。
5. “立即同步（写入文件）”会在确认后用网页当前数据覆盖绑定文件；开启“修改后自动同步”时也会显示覆盖说明并要求确认。
6. “解除绑定”只移除工作台中的授权，不会删除磁盘上的文件。

浏览器可能在重新打开页面后收回文件写入权限。此时设置页会显示失败原因，点击“立即同步”并重新授权即可。文件同步失败不会影响浏览器中的本机数据，也可以继续使用“导出 JSON”下载备份。

## 项目结构

```text
JobAssistant/
├── index.html
├── style.css
├── script.js
├── data/
│   ├── companies.json
│   ├── learning.json
│   ├── websites.json
│   └── quicklinks.json
├── assets/
│   └── icons/
└── README.md
```


当前 JobAssistant 文件夹中最主要的文件如下。
index.html
项目的页面入口和界面骨架，双击它即可启动工作台。
主要包含：
- 左侧导航和顶部栏
- 首页统计面板
- 企业管理列表及编辑弹窗
- 学习中心各模块
- 招聘网站页面
- 设置、备份和导入界面
- 各类详情弹窗、确认弹窗
它主要负责“页面中有哪些元素”，不负责具体数据处理。
style.css
项目的全部视觉样式文件。
主要负责：
- 页面布局、颜色、字号和间距
- 企业列表、学习卡片、网站卡片样式
- 表单和弹窗样式
- 图片画廊和大图预览
- 浅色、深色模式
- 不同窗口宽度下的布局适配
- 按钮悬停、提示和动画效果
script.js
整个项目最核心的逻辑文件，绝大部分功能都在这里实现。
主要包括：
- 页面导航和事件绑定
- 企业增删改查、搜索和筛选
- 投递统计、截止提醒和最近修改时间
- 学习记录管理及 LeetCode 表单规则
- 图片压缩、IndexedDB 存储和大图预览
- 招聘网站与常用链接管理
- LocalStorage 数据读写
- JSON 导入、导出、合并和覆盖
- 旧版本数据迁移
- 本地备份文件绑定和同步
- 表单校验、错误提示和删除确认
data/ 文件夹
保存项目首次运行时使用的初始或示例数据：
- companies.json：企业初始数据
- learning.json：学习中心初始数据
- websites.json：招聘网站初始数据
- quicklinks.json：首页常用链接初始数据
这些文件不是工作台运行时的实时数据。实际使用过程中产生的数据主要保存在浏览器的 LocalStorage 和 IndexedDB 中。
单目标定.png 和 双目标定.png 是当前放在 data 目录中的图片文件，但代码不会自动把它们加载到学习记录中。
README.md
面向使用者的项目说明文档，介绍：
- 如何启动工作台
- 当前具备的功能
- 数据保存位置
- 图片存储规则
- JSON 备份与恢复方法
- 本地文件同步的操作方式
- 项目目录结构
PROJECT_HANDOFF.md
面向后续开发和维护的交接文档。
它记录了：
- 项目技术约束
- 已经实现的功能
- 数据结构和存储架构
- 旧数据迁移规则
- 备份文件安全要求
- 关键 JavaScript 函数入口
- 后续修改时需要特别注意的问题
继续开发前应优先阅读这个文件。
JobAssistant-backup*.json
这是用户实际导出的完整个人数据备份，可能包含：
- 企业和投递信息
- 学习记录
- LeetCode 题目
- 模拟面试内容
- 招聘网站和常用链接
- Base64 格式的图片内容
这些文件属于个人数据，不能当作测试文件直接修改或覆盖。需要测试导入时应先复制一份副本。
其他目录
- assets/icons/：项目图标等静态资源
- .git/：Git 版本管理信息，不属于程序运行文件
- .gitignore：规定哪些文件不应提交到 Git，尤其应排除个人备份数据
整体关系可以概括为：index.html 定义界面，style.css 控制外观，script.js 实现功能，data/ 提供初始数据，浏览器本机存储保存实际使用数据。
